## Why Underlay moved in this lane

Poodle `0.3.0` to `0.4.2` alone leaves a second Poodle runtime. Underlay
`v0.9.8` declares exact `poodle-svelte` `0.3.0`, so Bun keeps a nested `0.3.0`
copy for `underlay/templates` while the app renders `0.4.2` — the app would
still run the old release through every retained template, and the invariant
"no `@inflatable-cookie/poodle-*` pin below `0.4.2`" would fail in the lock.

Underlay `v0.9.10` is the release that declares exact `poodle-svelte` `0.4.2`,
and its CHANGELOG names the consumer action: move the Underlay dependency tag
and regenerate the root locks. Underlay source is unchanged across
`v0.9.8`..`v0.9.10` (`ts/` diff empty; Rust diff is the workspace version
string only), so this is a pin move, not a behaviour move. The prior Poodle
`0.3.0` adoption in this repo (`8b042f53`, `f0dd253f`) paired the same two
moves, and `PAPERCUTS.md` records JS-only Underlay moves as friction because
they leave two Underlay identities.

## Call-site migration

None required. No removed `0.4.0` API is used:

- no `Slider`/`RangeSlider` usage, so no `appearance`→`variant`, no removed
  fallback-text helpers, and no `[data-appearance=...]` selectors;
- no removed Slider-family recipe hooks in app CSS;
- no `MarkdownEditor` `renderHtml` or `htmlPolicy` prop, so no trust-policy
  migration; `MarkdownEditor.renderHtml` remains type-compatible in any case;
- `Tabs` usage (`account/+layout.svelte`, `variant="pill"`, unpinned `items`)
  stays source-compatible with the `pinned` additive field and the partition
  rules.

Release-carried behaviour change accepted, not patched: `MarkdownEditor`
sanitizes the built-in `marked` preview by default in `0.4.0`.
`packages/acme-ui/src/nightfire/notes/TaskNotesEditor.svelte` uses that
built-in path, so task notes previews are now sanitized. No shim, no override,
no vendored Poodle.
