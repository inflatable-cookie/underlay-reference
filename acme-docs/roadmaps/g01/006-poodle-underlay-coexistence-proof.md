# g01.006 Poodle Underlay Coexistence Proof

## Goal

Prove that the Acme reference implementation can run Poodle and retained Underlay surfaces together in one app with Poodle-owned theme selection, starting in `acme-admin`.

## Why this matters now

Underlay roadmap `g01.042` has now narrowed the remaining Poodle contract uncertainty enough that the next risk is no longer component taxonomy. The next risk is whether a real consuming app can bootstrap Poodle tokens, keep a retained Underlay surface alive, and replace at least one page-level UI surface directly with Poodle without creating a second theme system or ad hoc compatibility drift.

## Scope

- [x] bootstrap the Poodle token stylesheet at the app root
- [x] make the selected app root use Poodle-owned theme attributes as the canonical theme, density, and control-size selection
- [x] keep one retained Underlay surface rendering under that Poodle-owned theme selection
- [x] replace one page-level Underlay primitive or generic composite with direct Poodle usage on the same page
- [x] record what temporary token aliasing or compatibility glue was required, if any
- [x] do not widen this batch into a full admin conversion, auth-flow rewrite, or portfolio-wide migration
